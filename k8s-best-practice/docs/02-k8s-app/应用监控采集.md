# 应用监控采集

应用监控指标采集分两步：

1. **应用侧**：暴露 Prometheus 指标端点。
2. **平台侧**：通过 Categraf 配置采集任务。

Categraf 部署参考：[K8S指标监控](../01-k8s-base/K8S指标监控.md)。

---

## 一、暴露指标（应用侧）

根据应用类型选择暴露方式。

### 1.1 通用应用：暴露 `/metrics`

应用自身通过 Prometheus client 暴露 `/metrics` 端点，例如：

- Go：`github.com/prometheus/client_golang`
- Node.js：`prom-client`
- Python：`prometheus-client`
- Java：
  - Micrometer采集，见章节1.2
  - JMX Exporter采集，见章节1.3
  - OTel JMX 扩展，见章节1.4

**三种 Java 采集方式指标格式与采集链路对比**：

| 方式 | 指标格式 | 传输协议 | 采集端 | 指标命名示例 | 适用场景 |
|---|---|---|---|---|---|
| Spring Boot + Micrometer | Prometheus text | HTTP pull | Categraf / KSM Agent | `jvm_memory_used_bytes{area="heap"}` | Spring Boot / Spring Cloud 项目 |
| JMX Exporter | Prometheus text | HTTP pull | Categraf / KSM Agent | `jvm_memory_heap_bytes_used` | 非 Spring Boot 或不愿改代码的 Java 应用 |
| OTel Java Agent / JMX | OTLP (protobuf) | gRPC/HTTP push | OTel Collector | `process.runtime.jvm.memory.usage` | 新项目需统一 Trace + Metrics |

> 统一用 Categraf / Prometheus 生态时，推荐 Spring Boot 用 Micrometer、非 Spring Boot 用 JMX Exporter，指标命名和采集链路更一致。OTel 方案适合需要统一 Trace + Metrics 的场景。

只需保证端点在集群内可访问

> **Spring Boot 与 JVM 采集方式的区别**：Spring Boot 项目优先用 [1.2](#12-spring-boot-应用micrometer--prometheus) 的 Micrometer 方案；非 Spring Boot 或不愿改代码的 Java 应用，用 [1.3](#13-非-spring-boot-的-java-应用jmx-exporter) 的 JMX Exporter Agent 方案。

### 1.2 集成Micrometer采集

**适用场景**：Spring Boot / Spring Cloud 项目。

引入依赖：

```Groovy
// build.gradle
implementation 'io.micrometer:micrometer-registry-prometheus'
```

```XML
<!-- pom.xml -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
    <version>1.13.6</version>
</dependency>
```

暴露端点：

```YAML
# application.yml
management:
  endpoints:
    web:
      exposure:
        include: prometheus,health
```

指标路径为 `/actuator/prometheus`，采集时在 Pod 上添加 `prometheus.io/path` annotation 显式指定路径。详见 [2.1 自动发现](#21-自动发现推荐)。


### 1.3 JMX Exporter采集

**适用场景**：非 Spring Boot 的 Java 应用，或不想改动代码、仅需要 JVM 指标的场景。

#### 1.3.1 准备 Agent 和配置

下载 jar 包：

```Bash
curl -L -o jmx_prometheus_javaagent.jar https://github.com/prometheus/jmx_exporter/releases/download/1.6.0/jmx_prometheus_javaagent-1.6.0.jar
```

创建 `config.yaml`：

```YAML
lowercaseOutputName: true
lowercaseOutputLabelNames: true
rules:
  - pattern: 'java.lang<type=Memory><HeapMemoryUsage>used'
    name: jvm_memory_heap_bytes_used
  - pattern: 'java.lang<type=Memory><NonHeapMemoryUsage>used'
    name: jvm_memory_nonheap_bytes_used
  - pattern: 'java.lang<type=Threading><ThreadCount>'
    name: jvm_threads_count
  - pattern: 'java.lang<type=GarbageCollector,name=(.*)><CollectionTime>'
    name: jvm_gc_collection_seconds
    labels:
      gc: "$1"
```

#### 1.3.2 构建镜像

在现有 Dockerfile 中追加以下配置（原有业务构建步骤和启动命令保持不变）：

```Dockerfile
# 原有业务镜像构建步骤 ...

COPY jmx_prometheus_javaagent.jar /jmx/jmx_prometheus_javaagent.jar
COPY config.yaml /jmx/config.yaml
EXPOSE 8089  # 端口可按需修改，需与 1.3.3 中启动参数及 Deployment metrics-port 标签保持一致

# 原有 ENTRYPOINT / CMD ...
```

构建并推送镜像：

```Bash
docker build -t <registry>/<app>:<tag> .
docker push <registry>/<app>:<tag>
```

#### 1.3.3 注入启动参数

在 Deployment 环境变量中注入：

```YAML
env:
  - name: JAVA_TOOL_OPTIONS
    value: "-javaagent:/jmx/jmx_prometheus_javaagent.jar=8089:/jmx/config.yaml"
```

同时在 Pod 中暴露 `8089` 端口，并打上发现标签：

```YAML
labels:
  app: <app>
  team: <team>
  metrics-scrape: "true"
  metrics-port: "8089"  # 与 JMX Exporter 启动参数中端口保持一致
```

> 8089 为示例端口，可根据实际环境调整。需确保 Dockerfile `EXPOSE`、JVM 启动参数中的 `=8089:` 以及 `metrics-port` 标签三处一致。

指标路径为 `/metrics`，采集任务可直接复用自动发现配置。
示例Demo

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: test-gateway
  namespace: demo
spec:
  replicas: 1
  selector:
    matchLabels:
      app: test-gateway
  template:
    metadata:
      labels:
        app: test-gateway
        # KSM Agent 自动发现标签
        metrics-scrape: "true"
        metrics-port: "8089"
      annotations:
        # 默认采集 /metrics，无需额外配置
        prometheus.io/path: "/metrics"
    spec:
      containers:
        - name: test-gateway
          image: mock-otel-sample:0.0.1
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 8080
            - containerPort: 8089
              name: metrics
          envFrom:
            - configMapRef:
                name: mock-app-config
          env:
            - name: JAVA_TOOL_OPTIONS
              value: "-javaagent:/jmx/jmx_prometheus_javaagent.jar=8089:/jmx/config.yaml"
            - name: SERVICE_NAME
              value: test-gateway
            - name: SERVER_PORT
              value: "8080"
            - name: LOG_FILE
              value: /tmp/test-gateway.log
            - name: LOG_FILE_PATTERN
              value: /tmp/test-gateway.%d{yyyy-MM-dd}.%i.log.gz
          volumeMounts:
            - name: jmx-agent
              mountPath: /jmx/jmx_prometheus_javaagent.jar
            - name: jmx-config
              mountPath: /jmx/config.yaml
              subPath: config.yaml
          readinessProbe:
            httpGet:
              path: /api/health
              port: 8080
            initialDelaySeconds: 20
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /api/health
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 20
      volumes:
        - name: jmx-agent
          hostPath:
            path: /opt/jmx/jmx_prometheus_javaagent.jar
            type: File
        - name: jmx-config
          configMap:
            name: jmx-exporter-config
```

### 1.4 OTel JMX 扩展

**适用场景**：新项目已规划 OTel Trace，希望 Trace + Metrics 统一采集。

在 Trace 接入时直接上报 JVM 指标，无需额外配置 Categraf 采集任务。详细接入说明参考：[Trace接入](https://c9xudyniiq.feishu.cn/docx/CR5ydpACdojoQbxFbaZcrc2qnif)。

### 1.5 中间件/数据库：Exporter

**适用场景**：MySQL、Redis、Kafka、Nginx 等中间件或数据库，自身不直接暴露 Prometheus 指标。

部署对应的 Exporter，以 Sidecar 或独立 Deployment 形式暴露 `/metrics` 端口。常见 Exporter：

| 中间件 | Exporter 示例 | 默认 metrics 端口 |
|---|---|---|
| Redis | `redis_exporter` | 9121 |
| MySQL | `mysqld_exporter` | 9104 |
| Kafka | `kafka_exporter` | 9308 |
| PostgreSQL | `postgres_exporter` | 9187 |
| MongoDB | `mongodb_exporter` | 9216 |
| Nginx | `nginx_exporter` | 9113 |
| Elasticsearch | `elasticsearch_exporter` | 9114 |

部署示例（Redis + Sidecar Exporter）：

```YAML
containers:
  - name: redis
    image: redis:7
  - name: redis-exporter
    image: oliver006/redis_exporter:latest
    env:
      - name: REDIS_ADDR
        value: "redis://localhost:6379"
    ports:
      - containerPort: 9121
        name: metrics
```

Pod 标签：

```YAML
labels:
  app: redis
  team: infra
  metrics-scrape: "true"
  metrics-port: "9121"
```

> 集群外中间件或无 K8s 场景的 Exporter，使用 [2.3 手动下发采集任务](#23-手动下发采集任务) 配置固定地址采集。

## 二、配置采集（平台侧）

推荐通过 Helm Chart 部署 Categraf，KSM Agent 内置 `app-metrics` job，自动发现集群内暴露 Prometheus 指标的应用 Pod。详细部署参考 [K8S指标监控](../01-k8s-base/K8S指标监控.md)。

### 2.1 自动发现（推荐）

Helm Chart 部署的 KSM Agent 默认启用应用指标自动发现（`appMetrics.enabled=true`），其工作原理：

1. 扫描集群内所有 Pod，保留打了 `metrics-scrape: "true"` 标签的 Pod。
2. 用 Pod 的 `metrics-port` label 替换采集地址端口。
3. 从 Pod 的 `prometheus.io/path` annotation 读取指标路径。
4. 自动透传 `namespace`、`service`（来自 `app` label）、`team` 等标签。

最终 Categraf 实际抓取的 URI：

```
http://<pod-ip>:<metrics-port><__metrics_path__>
```

应用方需在 Deployment 的 `spec.template.metadata` 下同时打标签和声明指标路径：

```YAML
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
  namespace: production
spec:
  replicas: 1
  selector:
    matchLabels:
      app: order-service
  template:
    metadata:
      labels:
        app: order-service
        team: payment
        metrics-scrape: "true"
        metrics-port: "8080"
      annotations:
        prometheus.io/path: "/metrics"
    spec:
      containers:
      - name: order-service
        image: <your-image>
```

不同应用路径示例：

| 应用类型 | 指标路径 | annotation 配置 |
|---|---|---|
| 通用应用 | `/metrics` | `prometheus.io/path: "/metrics"` |
| Spring Boot | `/actuator/prometheus` | `prometheus.io/path: "/actuator/prometheus"` |
| 自定义路径 | `/monitor/metrics` | `prometheus.io/path: "/monitor/metrics"` |

> 建议始终显式配置 `prometheus.io/path`，避免依赖默认值带来的路径不一致问题。

### 2.2 手动下发采集任务

仅用于集群外中间件或没有自动发现的场景。在 Flashcat 数据集成-数据采集模块，创建 Prometheus 采集任务，远程下发给 Categraf。

按指标路径选择 `urls`：

```TOML
# 通用 /metrics
[[instances]]
urls = ["http://<app-svc>.<ns>.svc.cluster.local:<port>/metrics"]
labels = { job = "<app>", service = "<app>" }

# Spring Boot /actuator/prometheus
[[instances]]
urls = ["http://<app-svc>.<ns>.svc.cluster.local:<port>/actuator/prometheus"]
labels = { job = "<app>", service = "<app>" }

# JMX Exporter
[[instances]]
urls = ["http://<app-svc>.<ns>.svc.cluster.local:8089/metrics"]
labels = { job = "<app>", service = "<app>" }

# 中间件 Exporter，以 Redis 为例
[[instances]]
urls = ["http://<redis-exporter-svc>.<ns>.svc.cluster.local:9121/metrics"]
labels = { job = "redis", service = "redis" }
```

## 三、标签规范

|标签|示例值|设置方式|用途|
|---|---|---|---|
|`env`|`prod`、`staging`|`[global.labels]`|环境区分，按环境配置告警|
|`cluster`|`prod-k8s-01`|`[global.labels]`|多集群场景区分来源|
|`namespace`|`default`、`production`|自动发现时自动透传|资源所属命名空间|
|`service`|`order-service`、`user-api`|Pod label `app` relabel 映射|服务名，灭火图拓扑按此聚合|
|`job`|`app-metrics`|`job_name`|采集任务类型标识|
|`team`|`infra`、`payment`|Pod label `team` relabel 映射|归属团队，告警按团队路由|

应用标签示例（位于 Deployment `spec.template.metadata.labels`）：

```YAML
labels:
  app: order-service            # → service="order-service"
  team: payment                 # → team="payment"
  metrics-scrape: "true"
  metrics-port: "8080"
```

全局标签由 Categraf Agent 配置统一维护：

```Plaintext
[global.labels]
env = "prod"
cluster = "prod-k8s-01"
```

## 四、验证

1. **本地验证指标是否暴露**

   ```Bash
   # 通用 /metrics
   curl http://<pod-ip>:<port>/metrics | head

   # Spring Boot
   curl http://<pod-ip>:<port>/actuator/prometheus | head

   # JMX Exporter
   curl http://<pod-ip>:8089/metrics | head
   ```

2. **在 Flashcat 或 Categraf 中查看指标**
   - 确认 `jvm_memory_heap_bytes_used`、`jvm_threads_count` 等指标已上报。
   - 确认 `service`、`namespace`、`team` 等标签符合预期。
