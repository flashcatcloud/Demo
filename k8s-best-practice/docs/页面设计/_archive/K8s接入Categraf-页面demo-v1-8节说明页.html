2运行环境要求

三条硬要求，不满足会在安装或启动时失败。

  • Kubernetes 1.19 ～ 1.37，Helm 3 及以上
  • 节点为 Linux，命名空间允许特权容器（privileged + hostNetwork）
  • 具备集群级只读权限（list/watch pods、services、endpoints、nodes）
  • 能访问服务地址 {{serverAddr}}
!
不满足此环境要求，请联系 Flashcat 技术人员提供支持。

3功能说明

装完能拿到什么，一眼看完。

每台节点部署一个 Categraf，负责四件事：

  • 主机指标：CPU、内存、磁盘、网络、负载，默认用 node_exporter 插件
  • 容器与 kubelet：容器资源用量，以及 kubelet 自身状态
  • kube-proxy：转发规则数量与同步耗时
  • 运维能力：任务通道（向节点下发命令）、服务拓扑（服务间调用关系）

后两项需要在控制台开启，其余默认开启。

集群里部署一个 Categraf（固定 1 副本），负责四件事：

  • K8s 对象状态：Pod、Deployment、Service、Node、PVC 的期望值与实际值
  • 应用指标 · 规范型：Pod 加 prometheus.io/* 注解即自动纳管，新增服务不用改配置
  • 应用指标 · 非规范型：不能改注解的中间件，加一段抓取配置即可，业务 Pod 不用动
  • 组件指标：CoreDNS、Calico / Cilium，可选控制平面

主机、kubelet、kube-proxy 不在此模式，需要 DaemonSet。

两类应用分别怎么接（能改注解 / 不能改注解）

能改注解：在 Pod 模板加 prometheus.io/scrape: "true" 和端口，自动纳管；以后新增服务零配置。

不能改注解：在 appMetrics.extraScrapeConfigs 加一条抓取规则（按 namespace / service / label 匹配），业务 Pod 不用重启。

两类可以并存；同一个服务只选一种，避免重复采集。

4配置文件

可粘贴的 values、渲染后的样子，以及变量到底替换在哪。

i
组合部署：把下面「节点级」与「集群与应用级」两段 values 合并成同一个 my-values.yaml，重复的 categraf:、operator: 块各保留一份即可。

节点级（DaemonSet）

① values（已代入左侧变量）

my-values.yaml
categraf:
  serverAddr: "{{serverAddr}}"
  clusterName: "{{clusterName}}"
  env: "{{env}}"
  heartbeatGid: "{{gid}}"
  config:
    interval: {{interval}}

operator:
  enabled: true
  userToken: "{{token}}"

nodeCategraf:
  enabled: true
  hostname: nodeName      # ident = 节点名；服务拓扑要求不可改
  securityContext:
    privileged: true
  hostExec:
    enabled: true         # 任务通道
  inputs:
    cadvisor: true
    nodeExporter: true
    hostNative:
      enabled: true

# 本模式不部署集群级组件（组合部署时删掉这三段）
ksmCategraf:
  enabled: false
kubeStateMetrics:
  enabled: false
appMetrics:
  enabled: false
coreDns:
  enabled: false
networkPlugin:
  calico:
    enabled: false
  cilium:
    enabled: false

② 渲染后的 config.toml（只读预览）

config.toml
[global]
hostname = "${HOSTNAME}"          # 取值 = spec.nodeName
interval = {{interval}}
providers = ["local", "http", "rmq"]   # 支持控制台远程下发

[global.labels]
env = "{{env}}"
cluster = "{{clusterName}}"
categraf = "nodeAgent"

[global.n9e_server]
address = "{{serverAddr}}"

[heartbeat]
enable = true
url = "{{serverAddr}}/v1/n9e-plus/heartbeat"
!
启动参数不可替换：容器固定 args: ["-configs", "/opt/categraf/conf"]。可变的只有 values → ConfigMap → 挂载文件；config.toml 是单文件挂载，不支持整目录覆盖。

集群与应用级（StatefulSet）

① values（已代入左侧变量）

my-values.yaml
categraf:
  serverAddr: "{{serverAddr}}"
  clusterName: "{{clusterName}}"
  env: "{{env}}"

operator:
  enabled: true
  userToken: "{{token}}"

ksmCategraf:
  enabled: true
  replicas: 1                   # 固定 1，多副本会重复抓取
  jobs:
    kubeStateMetrics: true

kubeStateMetrics:
  enabled: true

appMetrics:
  enabled: true
  defaultJob:
    enabled: true               # 场景一：规范注解自动发现
  extraScrapeConfigs: []        # 场景二：不合规范时在这里逐条加

# 本模式不部署节点级组件（组合部署时删掉这两段）
nodeCategraf:
  enabled: false
kubeProxy:
  enabled: false

② 场景一：业务侧要打的注解（给研发看）

Deployment / spec.template.metadata
metadata:
  labels:
    app: order-service      # → 指标标签 service
    team: platform          # → 指标标签 team
  annotations:
    prometheus.io/scrape: "true"
    prometheus.io/port: "8080"        # 容器端口，不是 Service 端口
    prometheus.io/path: "/metrics"    # Spring Boot 用 /actuator/prometheus
    prometheus.io/scheme: "http"

③ 场景二：不能改注解时，逐条加采集任务

my-values.yaml（追加）
appMetrics:
  extraScrapeConfigs:
    # 中间件 1：Redis Exporter（按 Service / Endpoints 抓）
    - job_name: redis-exporter
      kubernetes_sd_configs:
        - role: endpoints
      relabel_configs:
        - source_labels: [__meta_kubernetes_namespace, __meta_kubernetes_service_name]
          action: keep
          regex: middle;redis-exporter
        - source_labels: [__meta_kubernetes_endpoint_address_target_name]
          target_label: instance

    # 中间件 2：MySQL Exporter（按 Pod 标签抓，端口写死）
    - job_name: mysql-exporter
      kubernetes_sd_configs:
        - role: pod
          namespaces:
            names: [middle]
      relabel_configs:
        - source_labels: [__meta_kubernetes_pod_label_app]
          action: keep
          regex: mysql-exporter
        - source_labels: [__meta_kubernetes_pod_ip]
          target_label: __address__
          replacement: ${1}:9104
        - source_labels: [__meta_kubernetes_pod_label_app]
          target_label: service
        - source_labels: [__meta_kubernetes_pod_name]
          target_label: pod
i
每个列表项必须是完整、合法的 Prometheus scrape_config，Chart 只做追加。
只想按清单抓、彻底关掉规范发现：appMetrics.defaultJob.enabled: false（0.2.2 起）。
!
本模式不支持控制台远程下发：KSM Agent 的 providers = ["local"]，抓取目标只能通过 values 维护，改一次就要走一次 helm upgrade。

5部署并检查

一条命令装完，用三个信号确认成功。

bash
# 安装（在线）
helm upgrade --install {{release}} \
  oci://registry.flashcat.cloud/public/charts/categraf \
  --version {{chartVersion}} \
  -n {{namespace}} --create-namespace \
  -f my-values.yaml

# 安装（离线，已导入 chart tgz 与镜像）
helm upgrade --install {{release}} ./categraf \
  -n {{namespace}} --create-namespace \
  -f my-values.yaml
bash · 检查 DaemonSet
kubectl -n {{namespace}} get ds {{release}}
kubectl -n {{namespace}} get pods -o wide
kubectl get nodes --no-headers | wc -l      # 期望 Pod 数 = 节点数
bash · 检查 StatefulSet
kubectl -n {{namespace}} get sts {{release}}-ksm
kubectl -n {{namespace}} exec {{release}}-ksm-0 -- \
  cat /etc/categraf/cluster-scrape.yaml | grep job_name
验收（全打勾即接入完成）
i
常见失败：DESIRED > READY 多半是节点 taint 或 PSA 拒绝；up=0 多半是端口/路径写错（写成 Service 端口而不是容器端口）；设备离线先验证节点到 {{serverAddr}} 的网络。

6升级

升级只是换个版本号，但要先备份、并注意一个已知坑。

bash
# ① 备份当前 values
helm -n {{namespace}} get values {{release}} > {{release}}-values.backup.yaml

# ② 升级到指定版本
helm upgrade {{release}} \
  oci://registry.flashcat.cloud/public/charts/categraf \
  --version <新版本> \
  -n {{namespace}} -f my-values.yaml
bash · 观察滚动
kubectl -n {{namespace}} rollout status ds/{{release}}
# 从 0.2.1 / 0.2.2-rc.1 升级且 values 未变时，补一条：
kubectl rollout restart ds/{{release}} -n {{namespace}}
bash · 观察滚动
kubectl -n {{namespace}} rollout status sts/{{release}}-ksm
# 从 0.2.1 / 0.2.2-rc.1 升级且 values 未变时，补一条：
kubectl rollout restart sts/{{release}}-ksm -n {{namespace}}
!
0.2.2 起 checksum 基于渲染后的配置，升级会自动滚动 Pod。 DaemonSet 升级会短暂中断采集（秒级）。 StatefulSet 是单副本，升级期间有数秒抓取缺口，属正常。 回滚：helm rollback {{release}} <REVISION> -n {{namespace}}

7卸载

卸载不只有一条命令，还要先决定设备要不要保留。

bash
# 默认卸载：会顺带清理本集群在 Flashcat 上的设备
helm uninstall {{release}} -n {{namespace}} --wait

# 只删工作负载、保留设备
helm uninstall {{release}} -n {{namespace}} --no-hooks
!
operator.cleanup.nodeCategraf / ksmCategraf 默认 true：卸载会先停止采集、等设备心跳停止（最长 2 分钟）后删除本集群设备。清理只作用于本集群，不会删除业务组。需要保留设备请用 --no-hooks，或先把 cleanup 设为 false。

8其他说明

刁钻但一定会被问的场景，集中收口。

节点级场景

场景做法副作用
不开启 Node 采集nodeExporter: false + hostNative.enabled: falseFlashcat 主机大盘会空
开启 kubelet 采集inputs.cadvisor: true（默认已开）需 kubelet 10250 可达
自动注册到业务组categraf.heartbeatGid: "{{gid}}"设备心跳自动归组，控制台仍可手动移组
缩容自动删设备Operator 监听 Node 删除 → 观察期 → 校验心跳后删除只覆盖 DaemonSet，不覆盖 STS 缩容
多 Release 并存每个 Release 用不同 clusterName 与命名空间集群名重复会导致设备互串
Windows 节点不支持DS Pod 在 Windows 节点会失败
!
Operator 的自动清理只覆盖 Node Agent（监听的是 K8s Node 删除，不是 Pod 缩容）；KSM Agent 的设备只在 helm uninstall 时清理。

集群与应用级场景

场景做法注意
只想按清单抓appMetrics.defaultJob.enabled: false内置 app-metrics 关闭，只剩自定义 job
只抓指定命名空间自定义 job 里用 namespaces.names 收窄内置 job 是全命名空间
replicas > 1不建议每副本读同一份配置，会重复抓取
STS 缩容无自动清理设备需人工在列表删除
不部署 KSMkubeStateMetrics.enabled: false需已有 KSM，否则 up=0

i
组件采集按集群实际插件只留一个（Calico 或 Cilium），全开会产生 up=0 的无效 target。
